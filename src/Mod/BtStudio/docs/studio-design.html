1. Guardrails (every stage)

Ship in small overlay-only slices so a bad change cannot brick stock FreeCAD. BtStudio is loaded with FreeCAD -M src/Mod/BtStudio. If we break the overlay, launch without -M and FreeCAD is still upstream-shaped.

  • One stage in flight. Do not start the next until headless tests and the regression gate pass.
  • Tier 4 only. New/changed files under src/Mod/BtStudio/. No src/Gui, no Sketcher/PartDesign/FEM C++, no user RibbonStructure.json.
  • Additive first. Prefer a new command on an existing toolbar over regrouping or a new workbench.
  • Rollback is git revert of that stage’s BtStudio files. Stock workbenches are untouched, so Sketch/Pad/FEM still work.
  • Python only until a stage proves C++ is required (OVERVIEW default rule). Rebuild is not part of these stages.
Do not in any stage: patch FreeCAD-Ribbon JSON; rename stock command ids; replace CalculiX/Gmsh; embed this HTML inside FreeCAD; start hole-wizard, 3D sketch, or Fluids mesh/solve.

Considerations

Constraints we design around so Simulation and CAD stages do not depend on FreeCAD assembly being a SolidWorks-class product. Built-in Assembly is on the ribbon tab strip; it is not the geometry source for v1 analysis.

Built-in Assembly — nested sub-assemblies

Community report (Reddit, ~2025): the built-in Assembly workbench does not support multiple levels of nested sub-assemblies. An assembly inside an assembly inside a third assembly throws errors. Quote: the lack of a stable assembly workbench is one of the main drawbacks of FreeCAD; other assembly workbenches exist (A2plus, Assembly4, …) with mixed strengths and often unintuitive UX. Which workbench you pick changes what is even possible.

  • Simulation Geometry cell (stages 3–5): link a Part / PartDesign Body with Volume>0 — not a nested Assembly document. Multi-body boolean or a single fused solid is fine. Do not require “solve the assembly, then mesh.”
  • Do not reuse Assembly_CreateSimulation (joint MBD animation). That is not FEM.
  • Do not pick a third-party assembly WB (A2plus / Asm4) as a BtStudio dependency in stages 1–5. If we add assembly later, it is its own stage with an explicit workbench choice.
  • Ribbon still shows an Assembly tab (stock workbench). We do not redesign that tab in this spec.

If a user brings a nested assembly, the Geometry cell should say “pick a solid / Body” rather than trying to flatten the assembly tree.

1. Goal

Rebuild the Sketch ribbon so it matches modern CAD: a hybrid of always-visible Sketch + Part Design workbench tabs (FreeCAD-Ribbon still maps workbench → tab) and a contextual in-edit overlay that takes over the ribbon body while a sketch is open (Fusion / SolidWorks / Onshape).

  • Flagship gap: Insert DXF/DWG into the active sketch or a new sketch on a selected plane. Today File → Import creates Draft objects; dxfCreateSketch makes a new sketch, never the one you are editing.
  • Map every proposed button to a stock FreeCAD command, a BtStudio overlay, or a labeled gap.
  • Do not invent a DXF parser. After sign-off, reuse Draft importDXF / importDWG and Draft.make_sketch(..., addTo=active_sketch).

Analog: Fusion Insert DXF, Onshape Insert DXF or DWG on the sketch toolbar, SolidWorks Insert → Sketch from Drawing. Not Draft workbench hopping.

What exists today (workaround)

  1. File → Import a .dxf. Draft importDXF.py creates Draft objects (or a new sketch if pref dxfCreateSketch is on).
  2. Switch to Draft. Select objects. Draft_Draft2Sketch → another sketch.

Draft.make_sketch(objects, autoconstraints=…, addTo=existing_sketch) already supports appending into an open sketch. The gap is a Sketcher-ribbon command and a file picker that runs import + addTo without leaving the editor. DWG uses existing importDWG.py (DXF conversion) then the same path.

4. New Simulation click-path

  1. User is in a document that already has (or will have) a Part / PartDesign solid. Or they accept Create sample cube from the Geometry cell.
  2. Ribbon Simulation tab (Simulation workbench) → large New Simulation (BtStudio_NewSimulation — name TBD, not Assembly’s command).
  3. Create SimulationProject (FeaturePython group) in the active document.
  4. Default row: one Static Structural system with cells Geometry → Mesh → Setup → Solution → Results. Geometry cell links the selected solid if any.
  5. Open the schematic view + right task sidebar for the current cell only (same rule as evaluate_wizard: one Run enabled).
  6. Activate FEM workbench tools as needed; Simulation tab stays the project home.

Document tree (example)

Document ├── Body / Cube # CAD (Geometry cell link) └── SimulationProject # FeaturePython group ├── Geometry # PropertyLink → Body └── StaticStructural # wraps Fem::Analysis ├── SolverCcxTools # AnalysisType = static ├── MaterialSolid ├── ConstraintFixed ├── ConstraintForce ├── Mesh # Fem::FemMeshObjectGmsh └── Results # post pipeline

6. Object map

Each schematic cell is a view of existing FreeCAD types. We do not invent a second mesh or result stack.

Cell FreeCAD objects / commands Gating (today’s wizard facts)
Geometry Part / PartDesign Shape with Volume>0 (a Body or solid). Optional create_sample_cube. Not a nested Assembly — see Roadmap Considerations. geometry_ready
Model (mesh) BtStudio_FemAutoMesh → Gmsh Fem::FemMeshObject; MeshRegion = concentrations (ANSYS_MESHING_MAP.md). has_mesh
Setup Fem::Analysis + SolverCcxTools (fem_setup.create_analysis_container), FEM_MaterialSolid, type-specific constraints. has_analysis, has_material, has_constraint
Solution FEM_SolverRun (ccx). Working dir on the solver object. has_solver_run
Results FEM_ResultShow / post pipeline. Quantity depends on system (U, freq, T, buckling factor). has_results
2nd system (link) Another Fem::Analysis; Geometry PropertyLink to the same solid (Workbench share-geometry). Per-cell evaluate_wizard

ANSYS Mechanical pipeline in the current dock is geometry → analysis → material → BCs → mesh → solve. Workbench schematic often draws Mesh before Setup. That order is an open question below.

8. Open questions

Leave answers on this page or in chat. Blocking for first implementation:

Q1. Cell order: mesh before BCs? ANSYS Workbench draws Model (mesh) before Setup. The current FEM wizard meshes after constraints. Which order does New Simulation lock in?
Q2. One schematic per document, or many? Recommend one SimulationProject per document for v1; extra systems are extra columns, not extra projects.
Q3. Mesh cell action Click Mesh → always run Auto Mesh, or open the FEM mesh toolbar (MeshRegion, boundary layer) with Auto Mesh as the default Run?
Q4. Where does the schematic view live in the GUI? Central MDI (like a TechDraw page) vs a dedicated dock vs replacing the analysis wizard dock?
Q5. Workbench vs overlay Confirm Simulation is a real Python workbench (required for a Ribbon tab) living under src/Mod/BtStudio, Tier 4, no src/Gui edits.

9. First-implementation checklist (after sign-off)

  1. Python Simulation workbench (or BtStudio as workbench) so Ribbon grows a Simulation tab from toolbars.
  2. Command BtStudio_NewSimulation (not Assembly_CreateSimulation).
  3. SimulationProject FeaturePython group + Geometry link + Static Structural child wrapping create_analysis_container.
  4. Schematic editor: Qt QGraphicsView, cells bound to document objects, status from evaluate_wizard facts.
  5. Task sidebar still Next-only; ribbon Setup/Solve enable from the same facts.
  6. Headless tests on the graph model (no FreeCAD import), same pattern as python3 -m btstudio.tests.
  7. Human GUI check: New Simulation → cube → mesh → Fixed + load → solve → results. Modal/Thermal remain palette “coming” until wired.
  8. Update ANSYS_ANALYSIS_MAP.md and README once behavior exists.
  9. Split across Roadmap stages 3–5: objects + existing wizard first, then Ribbon tab, then schematic view.
