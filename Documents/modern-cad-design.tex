% ============================ THESIS ========================================
\section{Product thesis}

SolidWorks is the target \emph{feel} (FeatureManager, CommandManager-like strip,
familiar mouse, guided simulation). Fusion is the target \emph{shell} (ribbon
while modeling, dashboard on launch). FreeCAD is the \emph{foundation} (OCCT
kernel, Body/Tip history, workbenches, CalculiX + Elmer).

The gap is closed in this order, because that is the order the codebase actually
supports:

\begin{enumerate}[label=\textbf{\arabic*.}]
  \item \textbf{Shell} --- Home dashboard + Fusion-style ribbon over existing commands.
  \item \textbf{Look} --- YAML tokens, QSS, icons. Not a C++ widget rewrite.
  \item \textbf{Modeling UX} --- Body/Tip, naming, rollback, sketch-in-tree.
  \item \textbf{Mac smoothness} --- Qt/OpenGL mitigation now; Metal later.
  \item \textbf{Simulation} --- guided CalculiX plus Elmer first-principles as WIP.
\end{enumerate}

Keep the native macOS menu bar. The ribbon is the command strip, not a replacement
for File / Edit / View.

% ============================ WORKSTREAM A ==================================
\section{Workstream A \; CAD-familiar defaults}

Goal: a first launch that feels like SolidWorks / Fusion without touching
preferences. Vehicle: built-in preference pack plus shipped fallbacks.

\subsection{A1 \textemdash{} SolidWorks navigation}
Navigation styles live under \fp{src/Gui/Navigation/}. \fp{SolidWorksNavigationStyle}
already existed. New profiles now fall back to it, with turntable orbit and
object-center rotation (\fp{DefaultNavigationStyleName}, \fp{DefaultOrbitStyle},
\fp{DefaultRotationMode} in \fp{NavigationStyle.h}). Existing \fp{User.cfg} is not
migrated.

\subsection{A2 \textemdash{} Modern CAD behavior pack}
Pack at \fp{src/Gui/PreferencePacks/Modern CAD/}: SolidWorks nav, cube, combo-view
layout, \fp{UseRibbon=1}. Type is Behavior, not Theme --- apply on top of Light/Dark.

\subsection{A3 \textemdash{} View cube}
NaviCube top-right, size 132, rotate-to-nearest. Configurable via
\fp{BaseApp/Preferences/NaviCube}.

\subsection{A4 \textemdash{} First-start onboarding}
Start workbench \fp{FirstStart2024} flow applies the Modern CAD pack once
(\fp{ModernCADDefaultsApplied}), skipped in GUI tests. Copy mentions SW/Fusion nav
and the ribbon/dashboard.

\subsection{A5 \textemdash{} Fusion 360 navigation class}
No \fp{Fusion360NavigationStyle} yet. Fusion's input model (MMB-orbit, Shift+MMB-pan,
scroll-zoom) differs from SolidWorks. Additive subclass under
\fp{src/Gui/Navigation/}, register in \fp{SoFCDB.cpp}. Do not block shell/look on this.

\subsection{A6 \textemdash{} Fusion-style ribbon}
Originally deferred. Product decision reversed: ribbon \emph{replaces} classic
toolbars while a document is open.

\textbf{Shipped v0}
\begin{itemize}
  \item \fp{Gui::RibbonBar} / \fp{RibbonManager} consume the workbench \fp{ToolBarItem} tree.
  \item Tabs = toolbars; groups split on separators; workbench combo on the tab row.
  \item Hidden when the active MDI view is \fp{StartView}.
  \item Classic \fp{QToolBar}s hidden while ribbon is on; toggle actions hidden so
        visibility is not saved as off.
  \item Preference \fp{BaseApp/Preferences/MainWindow/UseRibbon} (default on; off in GUI tests).
  \item Ribbon sits above the MDI area, not inside the 22\,px unified title bar.
\end{itemize}

\textbf{Still to polish:} Fusion-sized captions, overflow, contextual tabs
(sketch vs feature), QAT (quick-access undo/save), and visual QA on Mac.

% ============================ WORKSTREAM D ==================================
\section{Workstream D \; Home dashboard}

The landing page must \emph{not} show the ribbon. It is a dashboard.

\subsection{D1 \textemdash{} Dashboard chrome}
\fp{StartGui::StartView} documents page is now Home: title, three metric cards
(recent files, project count, graphics backend), then projects, new-file cards,
recent files, examples. Metrics are placeholders for later health/solver widgets.

\subsection{D2 \textemdash{} Projects}
\fp{Start::ProjectsModel} stores folder paths under
\fp{BaseApp/Preferences/Mod/Start/Projects}. New Project picks a parent folder,
creates a named directory and a \fp{.freecad-project} JSON marker, then lists
the project. Clicking opens a file dialog in that folder. Not a SolidWorks
assembly project yet --- a workspace folder.

\subsection{D3 \textemdash{} Recommended next widgets}
\begin{itemize}
  \item Templates: Part, Assembly, Drawing; ``continue last Body''.
  \item Document health: recompute errors, sketch solver status.
  \item Pinned folders and in-page command search.
  \item Units / navigation style status.
  \item What's-new / first-run tips.
  \item Mac GPU warning when the OpenGL renderer string looks like Metal 90.x.
  \item License / rebuild timestamp for this fork.
\end{itemize}

% ============================ WORKSTREAM E ==================================
\section{Workstream E \; SolidWorks-like facelift}

Theming is YAML tokens + \fp{FreeCAD.qss} (\fp{StyleParameters::ParameterManager}),
not a C++ skin.

\subsection{E1 \textemdash{} Modern CAD Light / Dark}
New packs and YAML:
\begin{itemize}
  \item Light: chrome \texttt{\#F5F5F7}, accent \texttt{\#0066B3}, flat padding, light-gray 3D background.
  \item Dark: graphite \texttt{\#2D2D30}, brighter blue accent.
\end{itemize}
Apply from Preferences $\rightarrow$ Preference Packs, on top of the Modern CAD
behavior pack. Visual QA waits for a Mac launch.

\subsection{E2--E4 \textemdash{} Density, viewport, icons}
Larger toolbar icons (24/32), denser Feature tree, no classic purple viewport
gradient, PartDesign preview colors in \fp{src/Mod/PartDesign/Gui/StyleParameters.h},
optional SW-like sketch/feature glyphs. Ribbon already uses text-under-icon;
size/caption still need a Mac pass.

% ============================ WORKSTREAM F ==================================
\section{Workstream F \; Modeling kernel UX}

This is the real SolidWorks gap. Chrome cannot fake it.

\textbf{Today.} PartDesign is \fp{Body} + \fp{Tip} + history. Pad/Pocket/Fillet go through
\fp{ProfileBased} / \fp{DressUp}. Recompute is \fp{App::Document::recompute()} topo-sort.
Assembly is \fp{AssemblyObject} + OndselSolver joints (kinematic), not SW mates.

\textbf{Gaps vs SolidWorks}
\begin{itemize}
  \item F1 --- no real rollback bar on the history tip.
  \item F2 --- topological naming is still fragile after face edits.
  \item F3 --- sketch is a separate object; no single FeatureManager tree.
  \item F4 --- no in-context assembly edits / SW-style mates driving geometry.
\end{itemize}

Do not schedule F before D/E are usable on a Mac. When F starts, work in
\fp{src/Mod/PartDesign/} and \fp{src/App/Document.cpp}, not in QSS.

% ============================ WORKSTREAM G ==================================
\section{Workstream G \; Simulation / first principles}

\textbf{Today.} \fp{FemAnalysis} plus external solvers. CalculiX is the structural
workhorse. Elmer is the continuum-PDE path (elasticity, heat, flow, EM equation
objects under \fp{src/Mod/Fem/}).

\subsection{G1 \textemdash{} First Principles Study}
Command \fp{FEM_FirstPrinciplesStudy} (Model + Solve toolbars/menus): creates or
reuses an analysis, adds Elmer, attaches elasticity + heat equations, shows a
one-time WIP dialog. Does \emph{not} replace CalculiX, add contact, or invent a
SW Simulation study tree.

\subsection{G2--G4 \textemdash{} Wizard, CalculiX presets, contact}
Guided equation wizard (mesh / material / BC checklist); CalculiX static/thermal
presets that feel like SW Simulation studies; assembly-wide contact --- a large
gap, not a stub.

% ============================ WORKSTREAM B ==================================
\section{Workstream B \; macOS-native chrome}

\subsection{B0 \textemdash{} Traffic lights already native}
\fp{Gui::MainWindow} is a plain \fp{QMainWindow}. Qt/Cocoa draws the standard frame;
red/amber/green already sit top-left. No code move.

\subsection{B1 \textemdash{} Unified title + toolbar}
\fp{setUnifiedTitleAndToolBarOnMac(true)} in the MainWindow constructor. The ribbon
is \emph{not} placed in that unified bar (too tall); it is a widget above the MDI
area.

\subsection{B2 \textemdash{} Native dock \& floating toolbars}
Floating toolbars keep native Cocoa chrome. Overlay
\fp{src/Gui/Stylesheets/macos-native-chrome.qss} is appended on \fp{Q_OS_MAC}.

\subsection{B3 \textemdash{} NSWindow full-size content}
Content under the title bar / large-title behavior needs a new Objective-C++
\fp{.mm} shim. Precedent exists (QuickLook, 3Dconnexion) but no window-chrome
Cocoa code yet.

\subsection{B4 \textemdash{} Bundle identity \& appearance}
\fp{CFBundleIdentifier=org.freecad.FreeCAD},
\fp{NSRequiresAquaSystemAppearance=false}. Signing/notarization is a release
concern, not this branch.

% ============================ WORKSTREAM C ==================================
\section{Workstream C \; Apple Silicon \& M5 smoothness}

\subsection{Why M4/M5 feel laggy}
The 3D view is OpenGL via Coin3D + \fp{QOpenGLWidget}
(\fp{src/Gui/Quarter/QuarterWidget.cpp}, \fp{src/Gui/View3DInventorViewer.cpp}).
On macOS that OpenGL is Apple's Metal translation layer
(\texttt{OpenGL 2.1 Metal - 90.x}). M5 GPUs are Metal-4 oriented; the translation
path is the known hitch/crash source (upstream reports on M5 MacBook Air + macOS
Tahoe, slow Sketcher recompute on M4). Safe mode does not fix it. Qt~6.8.3 has a
related \fp{QMacAccessibilityElement} use-after-free on Tahoe.

More OpenGL tweaks will not close this gap. C5 (Metal / Qt RHI) is the real fix.

\subsection{C1 \textemdash{} Architecture pin}
\fp{CMAKE_OSX_ARCHITECTURES=arm64} when building on Apple Silicon; default
\fp{CMAKE_OSX_DEPLOYMENT_TARGET=11.0}.

\subsection{C2 \textemdash{} Optional LTO / \texttt{-mcpu=apple-m1}}
\fp{FREECAD_USE_LTO} and \fp{FREECAD_APPLE_SILICON_TUNING} are off by default.

\subsection{C3 \textemdash{} TBB}
\fp{find_package(TBB)} before compiler checks so \fp{HAVE_TBB} in
\fp{src/config.h.cmake} lights up ImportOCAF parallel paths.

\subsection{C4 \textemdash{} Faster startup}
All modules' \fp{InitGui.py} still run eagerly (\fp{src/Gui/FreeCADGuiInit.py}).
Deferral has ordering risk.

\subsection{C5 \textemdash{} Metal / Qt RHI}
Near-term (shipped): \fp{QSurfaceFormat::setSwapInterval(1)} on macOS; software
OpenGL fallback tooltip updated for M-series. Prefer Qt newer than 6.8.3 on
Tahoe when building. Do not treat nav cube, extra GL contexts, or QSS as the
root cause.
